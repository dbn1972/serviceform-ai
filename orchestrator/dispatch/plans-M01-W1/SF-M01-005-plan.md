## 2. packages/connector-sdk (pure library, no DB, no Fastify)
Dependencies: `@serviceform/contracts` (types + `validate`), nothing else. Node built-ins `node:crypto` for HMAC/timingSafeEqual, `node:timers/promises`.
- `src/spi.ts`: interface `ConnectorAdapter { readonly connectorType; readonly supportedModes; invoke(req: InvokeRequest, ctx: InvokeContext): Promise<InvokeResult>; verifyWebhook(req: RawWebhook, ctx): Promise<VerifiedWebhook>; health(ctx): Promise<HealthResult> }`. `InvokeContext` carries binding (frozen `ConnectorBinding` type), `SecretResolver`, `AbortSignal`, `correlation_id`, `idempotency_key`, `simulation?: {scenario, test_run_id}`. Results are discriminated unions (`ok | retryable_error | permanent_error | timeout`); adapters never throw for provider outcomes. Adapters never see raw secret_ref strings beyond calling `ctx.secrets.resolve(binding.secret_ref)`.
- `src/secrets.ts`: narrow port `SecretResolver { resolve(secretRef: string): Promise<SecretMaterial> }` (`SecretMaterial` is an opaque class whose `toString/toJSON/inspect` return `[REDACTED]`, value read via `.reveal()`). I define it myself; CMP-048 adapter plugged in later by wiring. Test double `InMemorySecretResolver` lives in `packages/connector-sdk/test/support` (not exported from src).
- `src/modes.ts` mode resolution: `resolveMode(binding, {deploymentEnvironment})` pure function. Server-side config only (Eng s10.1 rule 1): mode never comes from request input. Rules enforce frozen contract (validate via `validate('connector-binding', b)` first; failure = fail closed, error `BINDING_INVALID`) plus: binding.environment must equal the deployed environment; no fallback chain: resolution returns exactly the stored mode or throws; there is no code path that substitutes SIMULATED for REAL/SANDBOX (test greps for it and tests behaviour).
- Production fail-closed: `assertProductionSafe(bindings, env)` called (a) at service startup over all enabled bindings (`startupGuard` throws `ProductionSimulatedCriticalConnectorError`, process refuses to start; readiness stays false) and (b) on every invocation/webhook resolution (defence in depth, error SF-INT-001-class `CONNECTOR_MODE_FORBIDDEN`, no network call). Rule: env PRODUCTION and (SIMULATED any binding, or critical and mode != REAL) = refuse. Matches contract (SIMULATED limited to LOCAL/CI/DEV/SIT/PERFORMANCE; CI/LOCAL must be SIMULATED; PRODUCTION critical must be REAL). Whether non-critical PRODUCTION SANDBOX is acceptable: Q2.
- `src/retry.ts`: `executeWithResilience(fn, policy)`: per-attempt timeout via `AbortSignal.timeout` + Promise.race; exponential backoff with full jitter (`baseMs`, `factor`, `maxMs`, `maxAttempts`, injected `Clock`/`Sleeper`/`Random` for deterministic tests); retry only on `retryable_error|timeout`; never retry `permanent_error`; honour provider rate-limit hint (`retry_after_ms`) capped by policy; overall deadline. Policy defaults live in config (service config + per-definition `retry_policy` jsonb), no magic numbers in code (Q9 on default values).
- `src/circuit-breaker.ts`: per (binding id) breaker, states CLOSED/OPEN/HALF_OPEN, consecutive-failure + sliding-window failure-rate thresholds, `openMs`, single probe in HALF_OPEN. In-memory per worker, state exposed through `health()`. Cross-worker shared breaker state (needs Redis/DB) is out of scope: Q10. When OPEN: fail fast with SF-INT-001, emit Failed event with `error_code=CIRCUIT_OPEN`, no outbound call.
- `src/no-txn-guard.ts`: how "no outbound call inside an open DB transaction" is guaranteed, three layers:
  1. Structure: invocation is a 3-step saga in the service (section 4): TX1 (create transaction + Started event) commits, then provider call, then TX2 (finalise + Succeeded/Failed event). The only way to call an adapter is `ConnectorInvoker.run`, which takes a `UnitOfWork` port and calls `uow.assertNoOpenTransaction()` immediately before each attempt.
  2. Runtime guard: the service `UnitOfWork` wraps pg and tracks open transactions with `AsyncLocalStorage<{depth}>`; `assertNoOpenTransaction()` throws `OutboundCallInTransactionError` if the current async context is inside `withTransaction`. The adapter's HTTP client (`guardedFetch`, the only network egress helper exported by the SDK; adapters receive it via ctx) re-checks the same guard.
  3. Test (acceptance): integration test provider double, at call time, (a) asserts `uow.isOpen()===false`, and (b) opens a separate connection and queries `pg_stat_activity` for the test app's `application_name` rows with `state='idle in transaction'` (must be zero) and the invoker's pool client `txid_current_if_assigned()` is null. Plus a negative test that deliberately calls the invoker inside `withTransaction` and expects the throw and zero provider calls.
- `src/webhook.ts`: helpers: constant-time HMAC-SHA256 verify with timestamp tolerance (replay window), raw-body requirement, `ProviderReference` extraction by adapter. No provider specifics.
- `src/events.ts`: builders for the three events validated against `event-envelope` before returning (data validated by a connector-sdk JSON Schema? Cannot add to contracts/**: data schema kept as service-owned `services/cmp-037-integration-hub/contracts/events/*.schema.json`).
- `src/index.ts` exports; `package.json` (`@serviceform/connector-sdk`, private, type module, exports ./src/index.ts, scripts typecheck/build like packages/contracts), `tsconfig.json`.

CHECK constraints reproduce the contract's four conditional rules (PRODUCTION+critical => REAL; LOCAL/CI => SIMULATED; SIMULATED => simulator_version NOT NULL and environment in the five; REAL/SANDBOX => secret_ref NOT NULL) plus secret_ref regex `^(aws-sm|aws-ssm|vault)://[A-Za-z0-9/_.+=@-]+$`. 3. `connector_transaction` isolation TENANT_SCOPED, RLS ENABLE+FORCE same policy; sf_app SELECT/INSERT/UPDATE (no DELETE). Tenant FK composite so a transaction cannot reference another tenant's binding: `FOREIGN KEY (tenant_id, connector_binding_id)` -> unique(tenant_id, connector_binding_id).
Roles: only `sf_app` and `sf_outbox_publisher` exist; I create no roles, no BYPASSRLS. App sets tenant by `set_config('app.tenant_id', $1, true)` via `dbSessionSettings` inside TX (from @serviceform/contracts).
Idempotency for invoke: `Idempotency-Key` header + fingerprint stored on connector_transaction (my own table; I do not use another component's idempotency store). Same key + different fingerprint = SF-APP-002.

## 4. Invocation saga, webhook duplicate handling, events
Invoke (`ConnectorInvoker`, service layer):
1. Resolve context + authz (deny by default) -> TX1 (tenant set, RLS): load binding (wrong tenant returns nothing -> SF-TEN-002/404-style SF-SYS-002 without revealing existence), run mode/production guard, insert connector_transaction (ON CONFLICT on idempotency key: return existing outcome/replay), insert outbox ConnectorInvocationStarted, COMMIT.
2. No transaction open: resolve secret by handle, call adapter through `executeWithResilience` + breaker.
3. TX2: `UPDATE ... WHERE status IN (PENDING, IN_PROGRESS)` (optimistic, aggregate_version+1) to SUCCEEDED/FAILED + outbox Succeeded/Failed in the same TX. If the process dies between 1 and 3 the row stays IN_PROGRESS; a stale-reconcile is not built here (Q5).
Webhook (`POST /webhooks/{connectorId}`): unauthenticated, so tenant is unknown to RLS. Proposal (Q1): a SECURITY DEFINER function `cmp_037_integration_hub.resolve_webhook_binding(p_binding_id uuid)` (owner non-superuser, `SET search_path`, returns only tenant_id, connector_type, mode, environment, critical, secret_ref, simulator_version; EXECUTE granted to sf_app only) is the single non-RLS read; everything after runs under `set_config('app.tenant_id')` with the resolved tenant. Flow: raw body -> resolve binding -> production guard -> `adapter.verifyWebhook` (signature using secret handle; fail = 401 SF-AUTH-001, nothing persisted, no event) -> extract provider_reference -> TX: `INSERT connector_transaction ... ON CONFLICT (tenant_id, connector_binding_id, provider_reference) WHERE direction='WEBHOOK' DO NOTHING RETURNING`; only when a row was returned insert the outbox event and record in `inbox_event` (consumer_group `cmp-037.webhook`, event_id = deterministic uuid v5 of binding+provider_reference). A conflict returns 200 with the original outcome and writes nothing. Concurrent duplicates serialise on the unique index; a test fires N parallel identical callbacks and asserts count(connector_transaction)=1 and count(outbox_event)=1 for that reference. A same-reference callback with a different payload fingerprint is logged as an anomaly and still returns the original (no second event); flagged Q11.
Which event a webhook emits: Eng lists only the three; a webhook that reports success/failure maps to ConnectorInvocationSucceeded/Failed with `data.direction=WEBHOOK` (Started is not emitted for callbacks). Flagged Q12.
Event envelope fields: event_id uuidv4 (webhook: deterministic), tenant_id, cell_id (from RequestContext for invoke; for webhook from service config `CELL_ID`, Q13), correlation_id (from request or generated), actor `{type: 'INTEGRATION', id}`, aggregate_version = transaction version; partition_key = connector_transaction_id; each envelope validated with `validate('event-envelope', e)` before insert. Producer only INSERTs into outbox (template grants).

## 5. simulators/framework (reference echo simulator only)
Files in `simulators/framework/` (not a workspace member and I may not edit pnpm-workspace.yaml: Q14; sources imported by relative path from service/SDK tests, TypeScript compiled via the service tsconfig `include`). Content:
- `src/echo-adapter.ts`: `EchoSimulatorAdapter implements ConnectorAdapter` (type `DEPARTMENT_API`, modes SIMULATED only, `simulator_version` constant e.g. `echo-1.0.0`). `invoke` returns the request payload echoed, deterministic, driven by `scenario` in simulator config. Scenarios (lowercase per marker pattern): `success`, `fail_permanent`, `fail_transient_then_success`, `timeout`, `malformed_response`, `duplicate_callback`, `slow`. Deterministic: no `Math.random`/`Date.now` inside; ids derived by sha256(test_run_id+scenario+request_fingerprint+attempt).

- Every simulated result envelope carries `simulation: {…marker}` plus visible `"label": "TEST/SIMULATED"` and the same marker is persisted in `connector_transaction.simulation` and copied to the outbox event `data.simulation` (Eng s10.4). The hub rejects a SIMULATED invoke with no `test_run_id` (SF-SYS-003) and the simulated adapter result without marker (the hub validates every result from a SIMULATED-mode adapter and fails the transaction if the marker is missing or mismatched with binding id).
- `src/echo-webhook.ts`: signs callbacks with a test-only HMAC key obtained through the secret handle `vault://sim/echo-webhook` via the test `SecretResolver`; the callback goes through the real service webhook route and DB path (simulator replaces only the provider endpoint, Eng s10).
- `src/index.ts`, `tsconfig.json`, `README` NOT created (README.md is read-only). Version pinned: `simulator_version` stored in binding.
